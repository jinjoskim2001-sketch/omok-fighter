# 오목 파이터: 게임 UX, 연출, 사운드 리서치

이 문서는 SPEC 작성용 리서치다. 바로 결정할 수 있게 썼다. 기기에서 확인하기 전까지 불확실한 부분은 **[VERIFY]**로 표시했다.

## 0. 결정 요약

| 항목 | 권장안 |
|---|---|
| 착수 입력 | **두 번 탭으로 확정.** 누르고 있는 동안 돋보기(loupe)와 조준선이 나온다. 손을 떼면 미리보기 돌이 '장전'되고, 같은 자리를 다시 탭하면 착수된다. 설정에서 "바로 착수(한 번 탭)"를 고를 수 있고 기본은 끔 |
| 금수(쌍삼) 표시 | **미리 X 표시는 하지 않는다.** 금수 자리를 탭하면 그때 빨간 X, 흔들림, 버저, "쌍삼 금지!"가 나온다. 설정 "금수 미리 표시"는 기본 끔. 사용자가 '가이드 없이'를 원했고, 금수점이 보이면 그 자체로 수읽기 힌트가 된다 |
| 마지막 수 | 마지막 돌 하나에만 빨간 점(#FF3B30)을 찍는다 |
| 승리 라인 | 금색 라인을 0.3초에 걸쳐 그리고, 다섯 돌이 60ms 간격으로 차례로 커졌다 돌아온다 |
| 무르기 | 2P: 직전 내 수만 무를 수 있고 상대 허락이 필요하다. 라운드당 1회가 기본. CPU전: 내 수와 CPU 수를 함께 되돌리고 라운드당 3회가 기본 |
| 타이머 | 기본 없음. 10, 20, 30초 중 선택. 시간이 끝날 때 장전된 돌이 있으면 자동 착수, 없으면 TIME OVER로 라운드 패배 |
| 매치 | 단판, 3판 2선승, 5판 3선승, 7판 4선승. 이긴 라운드는 초상화 아래 핍(pip)으로 표시 |
| 흑(선공) 배정 | 1라운드는 동전 던지기 연출. 다음 라운드부터는 진 사람이 흑. 무승부면 색을 바꾼다. 설정으로 "번갈아"도 가능 |
| 렌더링 | 정사각 컨테이너에 canvas 3장(판, 돌, 효과)을 겹치고, 글자 연출은 DOM, 돋보기는 canvas 1장 |
| 연출 길이 | 라운드 사이 자동 진행은 약 3.6초, 탭으로 넘기면 최소 약 1초. 설정 "연출 속도"는 보통, 빠르게(×0.6), 최소 |
| 기본 판 테마 | **"배틀 장판"**(골판지 위 마커 격자, 비보이 배틀 매트 콘셉트). 그 외 네온 아케이드, 수련 도장, 8비트, 클래식 원목 |
| 사운드 | 오디오 파일 없이 Web Audio 합성만 쓴다. 컨텍스트 수명 관리는 품알 `js/audio.js`의 복구 단계를 그대로 재사용하고, 소리를 만드는 부분만 새로 짠다 |
| 이름 | **"돌주먹"**(부제: 오목 파이터) 추천. 홈 화면 라벨 3글자라 잘리지 않는다 |

## 1. 대국 화면 관례와 입력

### 1.1 칸 크기 (15×15, 판은 화면 폭 −12pt, 바깥 여백은 칸 0.6개씩이라 칸 크기는 판 폭 ÷ 15.2)

| 화면 폭(pt) | 기기 | 판 한 변 | 칸 크기 |
|---|---|---|---|
| 375 | SE 3세대, 13 mini | 363 | **23.9pt** |
| 390/393 | 13, 14, 15, 16, 16e | 378/381 | 24.9 / 25.1 |
| 402 | 16 Pro, 17, 17 Pro | 390 | 25.7 |
| 420 | iPhone Air | 408 | 26.8 |
| 430/440 | Plus, Pro Max | 418/428 | 27.5 / 28.2 |

모든 기기에서 칸 크기가 애플이 권장하는 최소 터치 영역 44pt의 절반 정도다. 돌 지름은 칸의 0.92배(약 22~26pt)인데, 손가락이 닿는 면이 이보다 넓다. 그래서 정밀 입력 보조 장치가 꼭 필요하다. 시중 앱들도 같은 문제를 각자 다른 방식으로 푼다.
- 확인 버튼 방식, 십자 커서, 자동 확대(일본 앱)
- 확대 후 착수, 슬라이드로 위치 선택(중국 앱)
- 누른 채 움직이다 떼면 착수(Touch-move-release, iOS 앱)
- 문지르듯 위치를 잡고 화면 아무 데나 터치해 확정(체코 앱)
- 체스닷컴과 BGA는 '확인'을 옵션으로만 둔다. 빠른 진행을 방해하기 때문이다.

결론: **확인 버튼 방식**은 친구끼리 여러 판 빠르게 두기엔 느리다. **누른 채 끌다 떼면 착수** 방식은 오착을 늘린다. 그래서 **두 번 탭으로 확정하되, 누르는 동안 돋보기를 보여 주는** 혼합 방식을 쓴다.

### 1.2 착수 입력: 정확한 동작 (기본 모드 "두 번 탭")

상태는 `IDLE`, `PRESSING`, `ARMED(p)` 세 가지다. 대국판 요소에 `touch-action:none`, `-webkit-user-select:none`, `-webkit-touch-callout:none`을 건다. 주 포인터(primary pointer)만 처리하고, 두 번째 손가락은 무시한다.

1. **pointerdown** (입력이 잠겨 있으면 무시)
   - 시작 좌표를 기록하고, 가장 가까운 교차점을 `target`으로 잡는다. 지금 장전된 점은 `prevArmed`로 기억해 둔다.
   - `target` 자리에 조준 표시(reticle, 아래 1.3)를 띄운다.
   - **150ms 이상 누르고 있거나 8pt 넘게 움직이면 돋보기를 띄운다.** 짧은 탭에 돋보기가 깜빡이는 것을 막기 위해서다.
2. **pointermove**
   - 시작점에서 8pt 넘게 움직이면 `dragging=true`.
   - 교차점 스냅에 히스테리시스를 둔다. 손가락이 현재 target 중심에서 **0.6칸** 넘게 벗어날 때만 target을 바꾼다. 바뀔 때마다 아주 작은 틱음을 내되, 40ms에 한 번까지만 낸다.
3. **pointerup**: 돋보기를 숨긴다.
   - `!dragging`이고 `prevArmed`가 있으며, 손을 뗀 좌표가 `prevArmed` 중심에서 **0.75칸 이내**면 **착수를 확정**한다. 장전된 점에 '끈끈한' 판정 반경을 주는 셈이다.
   - 그렇지 않을 때:
     - `target`에 이미 돌이 있으면 짧은 "톡" 거부음만 낸다. 장전 상태는 그대로 둔다.
     - 현재 둘 차례인 사람에게 `target`이 금수면 금수 피드백(1.3)을 주고 장전을 해제한다(IDLE).
     - 둘 수 있는 자리면 `ARMED(target)`로 바꾸고, 반투명 돌과 틱음을 낸다.
   - **끌다가 손을 떼면 장전만 하고 절대 확정하지 않는다.**
4. **pointercancel**: 돋보기를 숨기고 `prevArmed`로 되돌린다.
5. 차례가 바뀌거나, 무르기, 라운드 종료, 일시정지 때는 장전을 해제한다.
6. 착수를 확정한 뒤 **250ms 동안 입력을 잠근다.** 한 폰을 같이 쓰는 2P 대전에서 연타가 상대 차례로 새는 것을 막는다. 상대도 착수하려면 두 번 탭해야 하므로 이중으로 안전하다.
7. **돋보기 사양**
   - 원형 지름 112pt, 배율 2.2배. 손가락이 아니라 **스냅된 교차점**을 중심으로 그린다.
   - 위치는 터치 지점 96pt 위. 위쪽 공간이 모자라면 같은 높이의 반대쪽 옆으로 옮긴다.
   - 테두리 3pt는 현재 플레이어 색, 안쪽에 가는 십자선.
   - 구현: `drawImage(boardCanvas, …)`와 `drawImage(stoneCanvas, …)`로 확대해 그린 뒤 미리보기 돌과 조준 표시를 덧그린다.
8. **"바로 착수" 모드**(설정): 끌지 않은 탭은 즉시 착수한다. 끌다가 떼면 여전히 장전만 한다.
9. 처음 세 번 착수할 때만 한 번 "한 번 더 탭하면 착수!" 토스트를 띄운다. 조작법 안내일 뿐 수읽기 힌트가 아니다.

### 1.3 판 위 표시 (돌 반지름 r = 0.46칸)

- **미리보기 돌(장전 상태)**: 현재 색 돌을 불투명도 45%로 그린다. 조준 표시는 한 변 1.1칸짜리 사각형의 네 모서리 괄호이고, 현재 플레이어 색으로 1.2초 주기에 맞춰 불투명도가 70%와 100% 사이를 오간다. 손가락을 누르고 있는 동안에만 그 행과 열 전체에 18% 불투명도의 십자선을 보여 준다(정렬 확인용).
- **마지막 수**: 마지막 돌 중앙에 지름 0.24칸 빨간 점(#FF3B30)을 찍는다. 흑돌 위에서도 백돌 위에서도 잘 보인다. 착수 직후 1.2초 동안 테마 강조색 링을 한 번 퍼뜨린다(반지름 0.5칸에서 0.9칸으로 커지며 사라짐).
- **승리 라인**: 다섯 돌 중심을 잇는 선을 양끝으로 0.3칸씩 늘인다. 선 굵기 0.16칸, 둥근 끝, #FFD60A에 #FFB000 글로우(번짐 12). `lineDashOffset`을 움직여 280ms에 걸쳐 그린다. 각 돌은 60ms 간격으로 1.0→1.12→1.0배로 커졌다 돌아온다(각 180ms). 다섯 줄이 동시에 두 개 생기거나 장목(6목 이상)이면 해당 돌을 전부 강조한다. 다른 학생 프로젝트에서도 "다섯 돌이 차례로 금색으로 변하는" 연출을 썼다.
- **금수 시도**: 그 자리에 빨간 X(#FF3B30, 크기 0.5칸, 선 굵기 0.12칸)를 그리고 700ms에 걸쳐 사라지게 한다. 판은 좌우로 6pt, 3번, 180ms 동안 흔들린다. 버저음과 함께 "쌍삼 금지!" 토스트를 900ms 띄운다.
  - 쌍삼 금지가 흑만인지 흑백 모두인지는 규칙 담당 쪽에서 정한다. UX 쪽 권장은 **흑백 모두 금지**다. 친구끼리 설명하기 쉽고 대칭적이다. 어느 쪽이든 판정은 "현재 둘 차례인 사람" 기준이다.
- 좌표 라벨, 수순 번호, 힌트, 위협 강조는 **넣지 않는다.** '가이드 없이'라는 요구 때문이다.

### 1.4 무르기

| | 2P (한 폰으로) | CPU전 |
|---|---|---|
| 되돌리는 범위 | 방금 내가 둔 한 수(상대가 아직 두기 전까지만) | 내 마지막 수와 CPU의 응수, 두 수 |
| 승인 | 상대가 탭으로 허락. "1P: 한 수만 물러줘~" → [봐준다] / [안 돼] | 없음 |
| 횟수(라운드당, 설정) | 0, **1**, 3, 무제한 | 0, **3**, 무제한 |
| 라운드 종료(K.O.) 후 | 불가 | 불가 |
| 연출 | 돌이 1.0→1.3배로 커지며 160ms에 사라지고, 되감기음이 나온다. 버튼에 남은 횟수 표시 | CPU가 생각 중일 때 누르면 계산을 취소한다 |

무르기를 쓴 판도 전적은 정상적으로 집계한다.

### 1.5 타이머 (한 수당)

- 선택지: **없음(기본)**, 10초, 20초, 30초. 사람에게만 적용하고 CPU에는 적용하지 않는다.
- 표시: 현재 차례인 플레이어의 HUD 바가 체력 바처럼 줄어든다. 남은 5초부터 빨간색으로 바뀌고 매초 틱음이 난다. 남은 3초부터는 바가 깜빡이고 틱음이 더 높아진다.
- 시간이 다 되면:
  - 장전된 돌이 있으면 **그 수를 자동으로 착수**한다. 장전 단계에서 이미 금수 검사를 통과했으니 안전하다.
  - 장전된 돌이 없으면 **TIME OVER로 그 라운드를 진다.** 격투게임 관례와 같다.
- 일시정지 상태, 무르기 대화상자, 연출 중, `visibilitychange`로 앱이 숨겨진 동안에는 타이머를 멈춘다.

### 1.6 기권과 무승부

- **기권**은 일시정지 메뉴에 둔다.
  - "이번 판 기권": 해당 라운드를 상대에게 준다. K.O. 대신 "기권승" 배너를 띄운다.
  - "매치 포기": 매치 전체를 진다. 전적에 패로 기록한다.
  - 2P에서는 "1P 기권 / 2P 기권" 두 버튼을 보여 주고, 한 번 더 확인을 받는다.
- **무승부**: 225칸이 다 차거나, 둘 차례인 사람이 둘 수 있는 자리가 없으면(남은 칸이 모두 금수) 무승부다. 화면에 "DRAW — 판이 꽉 찼다!"를 띄운다. 핍은 주지 않고 라운드 번호만 올라가며, 다음 판은 색을 바꾼다.

### 1.7 흑(선공) 배정과 점수 표시

- 흑이 선공이고 선공이 유리하다는 건 정설이다. 대회에서는 Swap2 같은 오프닝 규칙으로 이를 보정한다. 친구끼리 하는 매치라면 아래 방식이 간단하고 공정하다.
- **1라운드**
  - 2P: "선공 결정" 동전 던지기 연출(1.2초, 탭하면 넘김). 흑백이 뒤집히는 돌이 두 초상화 사이를 오가다 한쪽에 떨어진다.
  - CPU전: 설정 "내 돌"에서 흑, 백, 랜덤 중 고른다. 기본은 랜덤.
- **2라운드부터**: 직전 판에서 **진 사람이 흑**(설정으로 "번갈아" 선택 가능). 무승부면 색을 맞바꾼다.
- **"한 판 더"(재대결)**: 직전 매치에서 진 사람이 1라운드 흑을 잡고, 동전 던지기는 생략한다.
- 라운드 시작 연출에서 "ROUND 2" 아래에 "1P 흑 · 선공"을 표시하고, 각 초상화 옆에 돌 아이콘을 붙인다.
- **핍**: 이겨야 하는 판 수만큼 핍을 둔다. 단판 1개, 3판 2선승 2개, 5판 3선승 3개, 7판 4선승 4개.
  - 한 판만 더 이기면 되는 플레이어 쪽에 "매치 포인트" 태그를 붙인다.
  - 두 사람 모두 매치 포인트면 라운드 시작 문구를 "FINAL ROUND"로 바꾼다.

### 1.8 이어하기

수를 둘 때마다 매치 상태를 localStorage에 저장한다(품알 `storage.js` 패턴). iOS는 백그라운드 PWA를 자주 종료시키기 때문이다. 앱을 다시 열면 타이틀 화면에 "이어하기"를 보여 준다.

## 2. 격투게임식 연출

### 2.1 캐릭터 선택

- 그리드는 **3×3**이고, **가운데 칸이 "?" 랜덤**, 둘레 8칸이 캐릭터다. 375pt 화면에서 칸 하나가 약 110pt라 누르기 넉넉하다.
- 그리드 위 미리보기 영역(약 180pt): 1P는 왼쪽, 2P는 오른쪽에 큰 전신 이미지를 서 있는 자세(idle)로 보여 준다. 이름과 한 줄 소개를 함께 띄운다.
- 커서: 1P는 빨강 #FF4757에 "1P" 태그, 2P는 파랑 #2E9BFF에 "2P" 태그.
- 선택 흐름
  - 칸을 탭하면 커서가 옮겨 가고 미리보기가 바뀐다.
  - 같은 칸을 다시 탭하거나 [결정]을 누르면 확정된다. 이때 흰색 섬광 80ms, 확정음, 캐릭터가 짧은 준비 자세를 취한다.
  - 1P가 확정하면 2P 커서가 나타난다.
  - [뒤로]는 마지막 확정을 취소한다.
  - 두 사람 다 확정하면 400ms 뒤 VS 화면으로 넘어간다.
- 같은 캐릭터끼리 붙는 미러전도 허용한다. 2P 쪽은 색만 바꾼 버전(팔레트 스왑, 예: `filter:hue-rotate`, 또는 캐릭터별로 지정한 대체 팔레트)으로 보여 준다.
- CPU전: 1P가 확정하면 CPU 커서가 칸 사이를 900ms 동안 랜덤으로 튀다가 멈춘다(1P와 다른 캐릭터).

### 2.2 VS 화면 (총 1.6초, 0.4초 뒤부터 탭으로 넘김)

| 시점 | 연출 |
|---|---|
| 0–300ms | 양쪽 초상화가 좌우에서 미끄러져 들어온다(살짝 튕기는 ease-out-back). 배경은 1P와 2P 색으로 대각선 분할 |
| 300ms | "VS" 글자가 3배에서 1배 크기로 200ms 만에 내려꽂힌다. 화면 흔들림 4px/150ms, 충돌음 |
| 500–1600ms | 이름과 스테이지 이름을 표시하며 유지 |

### 2.3 라운드 시작 (넘기지 않으면 약 1.2초)

1. "ROUND n" 표시 700ms. 텍스트가 크게 박힌 뒤 유지되고, 아래에 "1P 흑 · 선공".
2. "FIGHT!" 표시 500ms. 휙 소리와 함께 글자가 박혔다가 커지며 사라진다.
3. 2라운드부터는 전체 길이를 900ms로 줄인다. 마지막 판은 "FINAL ROUND".
4. 연출 중 탭은 연출을 넘기는 데만 쓴다. 판 입력은 연출이 끝나고 150ms 뒤에 열고, 연출을 넘긴 그 탭의 pointerup은 무시한다.

### 2.4 대국 화면 HUD (세로 모드)

```
[상단 안전 영역]
HUD 64pt : [1P 초상 52][이름·돌아이콘·핍 / 타이머바]  [ROUND n]  [타이머바 / 핍·돌·이름][2P 초상 52]
판      : 정사각형, 폭 = 화면 폭 − 12
무대    : 남는 높이 전부 (최소 88, 최대 200pt). 두 캐릭터가 마주 보고 서 있음
하단 바 56pt + 하단 안전 영역 : [무르기 (n)]   [차례: 1P 흑]   [일시정지]
```

- 375×667(SE) 기준 세로 배분: 상단 안전 영역 20 + HUD 64 + 판 363 + 무대 88 + 하단 바 56 = 591pt. 들어간다.
- **차례 표시**
  - 차례인 쪽 HUD 패널은 플레이어 색으로 빛나며 1.04배로 커진다. 반대쪽은 불투명도 50%로 흐리게.
  - 판 테두리 안쪽에 2pt 글로우를 현재 플레이어 색으로 넣는다. 흑돌 색으로 빛내면 어두운 테마에서 안 보이기 때문이다.
  - "1P/2P" 글자를 항상 붙여서 색약 사용자도 구분할 수 있게 한다.
- 타이머를 끄면 HUD 바 자리에는 이름과 돌만 표시한다. **형세 판단 바는 만들지 않는다.** 그 자체가 힌트가 되기 때문이다.
- v1.1 후보: 설정 "마주보기 모드". 2P HUD를 위쪽에 180도 돌려 놓아 테이블 양쪽에 앉아서도 각자 읽을 수 있게 한다.

### 2.5 대국 중 캐릭터 반응

- 착수할 때: 둔 쪽 캐릭터가 250ms 공격 모션(상대 쪽으로 앞으로 찌르기), 상대는 150ms 움찔한다.
- CPU가 생각하는 동안 CPU 초상화에 "생각 중…"이 깜빡인다. CPU는 수를 바로 계산했더라도 350~700ms 랜덤으로 기다렸다 둔다.
- **위협 상황(열린 3, 4 등)에 반응하는 연출은 넣지 않는다.** 그 자체로 힌트가 되기 때문이다.

### 2.6 K.O. 연출 (t=0은 다섯 줄을 완성한 돌이 확정된 순간)

| 시점 | 연출 |
|---|---|
| 0 | 돌이 떨어지는 애니메이션(110ms)과 착수음 |
| 110ms | **히트스톱 140ms.** 모든 CSS 애니메이션을 멈춘다(`.hitstop *{animation-play-state:paused}`). 흰 섬광(불투명도 0.35, 50ms) |
| 250ms | 화면 흔들림 320ms(진폭 8px에서 0으로, 약 30Hz, x와 y 모두). K.O. 타격음 |
| 250–650ms | 승리 라인을 그리고 돌이 차례로 커졌다 돌아온다 |
| 500ms | "K.O." 글자가 2.6배에서 1배로 140ms 만에 박힌다. 배경을 30% 어둡게 |
| 1400ms | 무대에서 승자는 라운드 승리 포즈(1.0초), 패자는 쓰러지는 모션 |
| 2000ms | 라운드 결과로 넘어간다(2.7절). 매치가 끝났으면 매치 결과 화면으로 화면 전환 효과(wipe) 300ms |

- 탭으로 넘기기는 **600ms 이후에만** 받는다. 마지막 착수 탭이 연출을 바로 날려 버리는 것을 막기 위해서다.
- `prefers-reduced-motion`이 켜져 있으면 흔들림과 섬광을 끄고, 글자는 박히는 대신 페이드로 나온다.
- 섬광은 한 번에 1회만. 광과민성 기준(초당 3회 이하)을 지킨다.

### 2.7 라운드 결과와 매치 결과

- **라운드 결과**(K.O. 이후 2000ms부터)
  - "1P WIN" 표시와 함께 핍이 채워진다(300ms, 반짝임과 효과음).
  - 판은 어둡게 깔린 채 남아 있다. 눈 모양 버튼을 **누르고 있는 동안** 오버레이를 걷어 판을 볼 수 있다.
  - 3600ms에 자동으로 다음 라운드 시작 연출로 넘어간다. 결과가 뜨고 1000ms 이후부터는 탭으로 바로 넘길 수 있다.
- **매치 결과** (승자 색 배경)
  - 승자: 큰 전신 이미지로 **고유 승리 모션**(2.0~3.0초)을 재생한 뒤, 승리 자세로 반복 재생한다. 승리 대사는 한 글자에 30ms씩 타이핑되듯 나온다.
  - 패자: 작게, 흑백 처리, 패배 자세.
  - 점수 "2 : 1", 라운드 요약 "R1 1P · R2 2P · R3 1P", "최단 K.O. 19수" 같은 통계.
  - 배지
    - 3판 이상 매치를 한 판도 안 지고 이기면 **"PERFECT"**.
    - 0:2처럼 뒤지다가 이기면 **"역전승!"**.
  - 버튼은 900ms 뒤에 나타난다: **[한 판 더!]**(같은 캐릭터, 같은 설정으로 바로 VS 화면), [캐릭터 변경], [메뉴].
  - CPU전에서는 "YOU WIN" / "YOU LOSE"를 띄운다. 내가 져도 CPU 캐릭터의 승리 모션을 재생한다. 스트리트 파이터식이고, 이 편이 더 재밌다.

### 2.8 연출 속도 설정

| 설정 | 동작 |
|---|---|
| 보통(기본) | 위에 적은 시간 그대로 |
| 빠르게 | 모든 연출 시간 ×0.6, VS 화면 유지 시간 0 |
| 최소 | 흔들림, 히트스톱, VS 화면 없음. K.O.는 400ms, 라운드 결과는 1초 |

라운드 사이 자동 진행은 약 3.6초(보통)이고, 탭으로 넘기면 약 1초다.

### 2.9 전적 (localStorage에만 저장, 완료된 매치만 기록)

- 전체 매치 수와 라운드 수
- 캐릭터별 사용 횟수와 매치 승률
- CPU전 난이도별 승패와 최장 연승
- 최단 K.O.(가장 적은 수로 이긴 판)와 최장 라운드
- 최근 매치 20개(날짜, 캐릭터, 점수)
- 선택 기능: 캐릭터 선택 화면에서 이름표를 탭해 플레이어 이름을 정하면 이름별 상대 전적("진조 vs 민수 7:5")도 쌓는다.
- [기록 초기화]는 확인을 두 번 받는다.

## 3. 판 테마 5종과 돌 렌더링

공통 렌더링 구조

- 정사각 컨테이너에 canvas 3장을 겹친다. DPR은 `min(devicePixelRatio, 3)`.
  - `board`: 정적. 테마나 크기가 바뀔 때만 다시 그린다.
  - `stones`: 착수할 때마다 다시 그린다.
  - `fx`: 미리보기 돌, 조준 표시, 링, 승리 라인, X.
- 바깥 장식은 판 여백 0.6칸 안에서만 그린다. **격자는 회전하거나 원근을 주지 않는다.** 터치 좌표 판정이 단순해야 하기 때문이다.
- 화점 5개는 (3,3), (3,11), (11,3), (11,11), (7,7)이다(0부터 센 좌표).
- 무거운 글로우(`shadowBlur`)는 화면 밖 canvas에 한 번만 그려 둔다.
- 테마를 캐릭터의 '홈 스테이지'로 묶는다. 설정 "스테이지"에서 랜덤, 1P 홈, 고정 중 고른다.

### 3.1 배틀 장판 (기본): 비보이 골판지 배틀 매트

- 페이지 배경: 콘크리트 #2B2B2E. SVG `feTurbulence`(baseFrequency 0.9) 노이즈를 6% 불투명도로 깐다.
- 판: 크라프트지 #C9A06A. 골판지 결은 `repeating-linear-gradient(90deg, rgba(0,0,0,.035) 0 2px, transparent 2px 7px)`. 긁힌 자국은 어두운 방사형 그라디언트 3~4개를 고정 시드로 배치한다.
- 격자: 검은 마커색 #1E1A16, 불투명도 0.85, 1.5px. 선마다 ±0.4px로 살짝 흔들리는 2차 곡선으로 그리되, 시드를 고정해 매번 같은 모양이 나오게 한다. 바깥 테두리선은 2.5px.
- 화점: 마커로 찍은 점, 반지름 0.12칸. X는 금수 표시와 헷갈리므로 쓰지 않는다.
- 장식: 네 모서리 여백에 은색 덕트테이프(#B8BCC2, 광택 그라디언트, 불투명도 0.85, ±40° 기울임). 판 밖에는 크루 스티커 느낌의 도형.
- 움직임: 판 자체는 정지. 착수할 때 베이지색 먼지 입자 6개가 180ms 동안 튄다.
- 돌: 기본 광택 돌에 그림자를 조금 진하게.

### 3.2 네온 아케이드

- 페이지: #07071A 바탕에 가운데 #2A0B4A 방사형 그라디언트.
- 판: #0E1030.
- 격자: #19E3FF 1px, 글로우(shadowBlur 6, rgba(25,227,255,.8)). 바깥 테두리는 마젠타 #FF2BD6 2px에 글로우.
- 화점: 마젠타 마름모.
- 스캔라인: `repeating-linear-gradient(0deg, rgba(255,255,255,.03) 0 1px, transparent 1px 3px)`. 격자와 돌 사이 층에 둬서 돌을 가리지 않게 한다.
- 움직임: 격자 층 불투명도가 3초 주기로 0.85와 1 사이를 오간다. reduced-motion이면 끈다.
- 돌: 흑돌에는 시안 테두리(0.08r, 불투명도 0.9)와 바깥 글로우 0.2r를 넣는다. 어두운 판에서 흑돌을 읽히게 하려면 이게 필수다. 백돌에는 핑크 #FF8AE6 글로우를 60%로 넣는다.

### 3.3 수련 도장 (다다미)

### 3.6 돌 렌더링 레시피 (canvas, 테마별 이미지를 미리 만들어 캐시)

돌 이미지는 화면 밖 canvas(한 변 `ceil(2.4r·dpr)`)에 미리 그려 두고, 착수할 때마다 `drawImage`로 찍는다.

| | 흑돌 | 백돌 |
|---|---|---|
| 그림자 | rgba(0,0,0,.45), 오프셋(0.06r, 0.12r), 번짐 0.15r | 같음, 불투명도 .35 |
| 몸통 | `radialGradient(cx−.35r, cy−.4r, .05r → cx, cy, r)`: 0 #7A7A80, .18 #3A3A40, .65 #141416, 1 #000 | (cx−.3r, cy−.35r 기준): 0 #FFFFFF, .55 #F1F1EC, .9 #CFCFC6, 1 #A9A99E |
| 하이라이트 | (−.32r, −.38r) 위치에 rx .28r, ry .16r, −35° 기운 타원, rgba(255,255,255,.28) | 작은 점 rgba(255,255,255,.9) |
| 가장자리 | 테마 테두리 글로우(네온만 시안) | 0.04r rgba(0,0,0,.25) 선 |
| 떨어지는 애니메이션 | 1.35배에서 1.0배로, 불투명도 0.6에서 1로, 110ms, `cubic-bezier(.2,.9,.3,1.3)`(살짝 튕김). 테마 색 충격 링이 0에서 1.2칸으로 퍼지며 불투명도 0.5에서 0으로, 220ms | 같음 |

**글꼴**: 연출용 큰 글자는 **Black Han Sans**(SIL OFL 1.1)를 저장소에 직접 넣는다. fonttools의 `pyftsubset`로 실제 쓰는 문구와 라틴 글자만 남겨 woff2 30~60KB 정도로 줄이고 서비스 워커 캐시에 넣는다. 본문은 시스템 글꼴(`-apple-system`, `"Apple SD Gothic Neo"`)을 쓴다. 8비트 테마에서만 품알이 쓴 NeoDunggeunmo를 써도 된다.

## 4. 사운드 (Web Audio 합성만 사용)

### 4.1 구조

- **컨텍스트 수명 관리는 품알 `js/audio.js`를 거의 그대로 가져온다.**
  - `touchend`, `click`, `keydown`에서 잠금 해제
  - `audioSession='ambient'`
  - `statechange` 감시
  - "running인데 시계가 멈춘" 상태를 잡는 워치독, suspend 후 resume, 탭할 때 컨텍스트 재생성
  - 앱이 숨겨지면 즉시 무음, 멈춘 시계에는 소리를 예약하지 않음
  - 이 사다리는 WebKit 버그 291892(백그라운드 복귀 후 무음)와 iOS 26.0.1의 resume 실패 보고에 대응해 만든 것이다.
- **바꿀 부분**: 품알의 출력 경로(800Hz 하이패스, 사각파 버저 전용)를 다음으로 바꾼다.
  - `voices → master gain(0.9 × 설정 볼륨) → DynamicsCompressor(threshold −14dB, knee 6, ratio 4, attack 3ms, release 150ms) → destination`
  - 컨텍스트를 만들 때 함께 준비할 것: 1초 길이 화이트노이즈 버퍼 1개, 1.6초 합성 잔향 IR(노이즈에 지수 감쇠를 건 것) `ConvolverNode` 1개, `tanh` WaveShaper 1개.
  - 패치 형식은 데이터 테이블로 둔다: `{layers:[{src:'noise'|'sine'|'tri'|'square'|'saw', f0, f1, glideMs, filter:{type,f,Q}, peak, attackMs, decayTau, durMs}], reverb}`.
- **잠금 해제 동선**: 타이틀 화면의 "화면을 터치하세요"가 첫 제스처가 된다. 오락실 관례와 iOS 오디오 잠금 해제가 한 번에 해결된다.
- **아이폰 스피커 특성**: 300Hz 아래는 거의 들리지 않는다. 그래서 무게감은 저역 사인파보다 배음(사각파, 웨이브셰이퍼)과 600Hz~3kHz 대역으로 만든다. 저역 사인파는 이어폰용 덤으로만 둔다.
- 소리끼리 겹칠 때: K.O.가 울리면 커서 틱 같은 작은 효과음은 바로 끈다. 같은 효과음은 40ms 안에 다시 울리지 않게 한다.

### 4.3 볼륨과 설정

- 볼륨 계층: 메뉴 틱 0.05~0.1, 착수 약 0.5, 연출음 0.3~0.7, K.O. 0.9. 압축기가 최종 피크를 잡아 준다.
- 설정 항목
  - 효과음: 켬/끔, 크기 3단계(작게 0.5, 보통 0.8, 크게 1.0)
  - **"무음 모드에서도 소리"**: 기본 끔. 켜면 `navigator.audioSession.type='playback'`으로 바꾼다.
    - 장점: 무음 스위치를 켜 둬도 소리가 난다.
    - 대가: MDN 설명상 'playback'은 다른 재생 오디오를 멈추는 배타적 세션이다. 그래서 켤 때 "켜면 듣던 음악이 멈춰요"라고 알린다.
    - 기본 'ambient'는 무음 스위치를 따르고 음악과 섞여 재생된다.
    - 실험적 API다. **[VERIFY]** iOS 26, 27 실기기에서 실행 중에 타입을 바꾸면 컨텍스트를 다시 만들어야 하는지 확인.
- `<audio>` 요소는 쓰지 않는다. 쓰면 미디어 세션으로 바뀌어 품알 주석에 적힌 문제가 생긴다. `speechSynthesis` 아나운서도 쓰지 않는다(음성 품질 문제, 세션 문제).
- **햅틱**: 품알 `haptics.js`(`<input switch>`를 감싼 label 오버레이)를 재사용한다.
  - 메뉴 버튼과 판 컨테이너에 붙인다. 판에서는 탭할 때마다 틱이 한 번 난다.
  - 포인터 좌표는 `offsetX`가 아니라 `clientX/Y − canvasRect`로 계산한다. label이 이벤트 대상이 되기 때문이다.
  - iOS 26.5부터는 진짜 탭에서만 동작하므로 K.O. 진동 같은 건 불가능하다. 그대로 받아들인다.
  - **[VERIFY]** label 오버레이 위에서 `setPointerCapture`, 끌기, 돋보기가 정상 동작하는지.

```

  - 판 수 · 시간제한 · 무르기 · 스테이지 · (CPU: 난이도, 내 돌)
```

## 7. 실기기 확인 목록 [VERIFY]

1. 판 위 햅틱 label 오버레이와 포인터 캡처, 끌기, 돋보기가 함께 동작하는지. 안 되면 판에서만 햅틱을 끈다.
2. `audioSession.type`을 'ambient'와 'playback' 사이에서 실행 중에 바꿀 때 iOS 26, 27에서 컨텍스트를 다시 만들어야 하는지.
3. iPhone SE(375×667)에서 HUD, 판, 무대, 하단 바가 안전 영역 안에 들어가는지. 돋보기가 위쪽 HUD에 걸릴 때 옆으로 옮겨지는지.
4. 3배 DPR에서 canvas 3장과 돋보기의 프레임레이트, 착수 애니메이션 중 다시 그리는 비용. 네온 테마 글로우는 반드시 미리 그려 둔다.
5. 0.75칸 확정 반경과 0.6칸 히스테리시스가 23.9pt 칸에서 적절한지. 친구 2~3명이 직접 해 보고 0.65~0.85 범위에서 조정한다.
6. Black Han Sans 서브셋에 모든 UI 문구 글자가 들어 있는지. 테스트에서 문구 테이블과 서브셋 글자 목록을 대조한다.
